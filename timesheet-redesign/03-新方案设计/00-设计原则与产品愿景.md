# 设计原则与产品愿景

**状态：** 草案，待评审

---

## 1. 产品愿景（一句话）

> 让员工 **确认** 本周工时，而不是 **回忆并填写** 本周工时。

---

## 2. 设计原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **草稿优先，表格兜底** | 默认草稿列表；grid 作为「高级模式」 |
| 2 | **来源可追溯** | 每行标注 Booking / 代发 / 日历 / 手动 |
| 3 | **规则不可妥协** | Booking、预算、24h 上限由引擎强制执行 |
| 4 | **移动确认，PC 精编** | 手机做确认；复杂编辑以 PC 为主 |
| 5 | **AI 辅助，人始终在环** | AI 只建议，不自动提交（除已有自治规则） |
| 6 | **飞书原生** | 待办、日历、项目、IM 一体，不另建 silo |

---

## 3. 信息架构（新导航草案）

| 原 Tab | 新结构建议 |
|--------|------------|
| 工时填报 | **我的本周**（草稿首屏） |
| 工时发送 | **代发工时**（独立入口，可从会议跳入） |
| 工时复核 | **待我接收**（PM） |
| 工时查询 | **我的记录** + **团队分析**（管理） |
| 项目工时 | 合并进「我的本周」周汇总区 |
| 汇报填写 | _待确认是否独立_ |
| 系统设置 | 保留 |
